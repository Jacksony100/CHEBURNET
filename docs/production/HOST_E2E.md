## Воспроизведение

На хосте не нужно создавать `C:\cheburnet-e2e-vm.marker`.
Из обычного **64-разрядного Windows PowerShell**:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\e2e\Build-CheburnetHostE2E.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\e2e\Invoke-CheburnetHostE2E.ps1 `
    -BuildManifest .\build-host-e2e\host-e2e-build.json -ResultsDir .\artifacts\host-e2e-new-run
```

Сначала выполняется обычная роль, затем UAC запускает повышенную фазу.
Для каждой новой попытки использовать свежий каталог результатов и новую сборку:
скрипт сборки генерирует новый идентификатор по умолчанию. Обе сборки используют
`/W4 /WX` и MSVC `/analyze`.

## Изоляция

`CHEBURNET_E2E_INSTANCE` задаётся **при сборке** и принимает только 16 строчных
шестнадцатеричных символов. Тестовый EXE называется `CHEBURNET-E2E.exe`; его
фиксированный корень — Known Folder ProgramData плюс `CHEBURNET-E2E-<id>`.
Блокировка экземпляра также имеет отдельное имя. В обычной сборке корень
по-прежнему фиксирован как CHEBURNET; перенаправления через CLI, конфигурацию
или переменные окружения нет.

Перед изменением файлов оснастка сверяет SHA-256 двух EXE и их ответы
`--e2e-identity`. Обычный EXE на эту команду возвращает код 2 до bootstrap/UI.
Существующий тестовый каталог, работающий winws или любая служба WinDivert
запрещают начало повышенной фазы.

Очистку выполняет нативный помощник через `securefs::RemoveTreeUnder`, с
проверкой собственного фиксированного корня и без обхода reparse points.
Рабочая установка CHEBURNET не очищается и не восстанавливается из резервной
копии: тест не получает разрешения изменять её.

## Драйвер

Помощник проверяет распакованную среду и загружает DLL из защищённого каталога.
Он эксклюзивно создаёт собственную службу WinDivert, сохраняя её дескриптор;
существующая служба не принимается, не останавливается и не удаляется.
Создание службы до вызова DLL также исключает запись DLL в ключ EventLog.
При завершении снимается только собственная служба, затем очищается тестовое
дерево. В обычный CTest этот тест драйвера не включён: его явно запускает
координатор проверки на хосте.

Семантика фильтра и SNIFF описана в
[документации WinDivert](https://reqrypt.org/windivert-doc.html#divert_open).
Поведение установки службы сверено с
[исходниками WinDivert 2.2.2](https://github.com/basil00/WinDivert/blob/v2.2.2/dll/windivert.c).

Отчёты имеют `environment_kind=host-isolated-build`. Валидатор чистой матрицы
Windows 10/11 такие отчёты отклоняет. Управление соединением через UI, реальные
обновления из сети и эффективность стратегий на трафике остаются отдельными
проверками.
